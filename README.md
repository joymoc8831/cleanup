# スカッドボード（GitHub Pages版）

サッカーチームのフォーメーションボードアプリです。名鑑（選手一覧）とチームボード（8〜10グループ分）を、Firebase（無料プラン）を使って全員で共有・自動保存します。

## できること

- 名鑑（FW・MF・DF／GK）を全員が同じ内容で閲覧・編集できます（写真・名前・一言）
- チームボードは10グループ分あり、タブで切り替えられます。全グループの配置を誰でも見られます（オーナーだけに限定する機能は現時点ではありません。必要であれば追加できます）
- スマホ・PCどちらのブラウザからでも使えます

## 事前準備：ファイルの中身

このフォルダには次のファイルが入っています。

- `index.html` … アプリ本体（このまま使います。編集不要）
- `firebase-config.js` … Firebaseの接続設定を書き込むファイル（**要編集**）
- `firestore.rules` … Firestoreのアクセスルール（Firebaseコンソールに貼り付けます）
- `README.md` … この説明書

---

## 1. Firebaseプロジェクトを作る（無料・5分程度）

1. [https://console.firebase.google.com/](https://console.firebase.google.com/) にGoogleアカウントでログインします。
2. 「プロジェクトを作成」→ 好きなプロジェクト名を入力（例：`squad-board`）→ 画面の指示通りに進みます（Googleアナリティクスは無効のままで問題ありません）。
3. プロジェクトが作成されたら、左メニューの「構築」→「Firestore Database」を開き、「データベースの作成」をクリックします。
   - ロケーションは `asia-northeast1`（東京）などお好みで選択します。
   - セキュリティルールは、最初は「テストモード」でも「本番環境モード」でもどちらでも構いません（あとで3.の手順で上書きします）。

## 2. ウェブアプリを登録して設定値を取得する

1. Firebaseコンソールの左上、プロジェクト名の横にある歯車アイコン →「プロジェクトの設定」を開きます。
2. 下の方の「マイアプリ」欄で `</>`（ウェブ）アイコンをクリックし、アプリのニックネームを適当に入力して「アプリを登録」します（Firebase Hostingは使わないので、そのままで構いません）。
3. 表示される `firebaseConfig = { ... }` の中身をコピーします。
4. このフォルダの `firebase-config.js` を開き、`YOUR_API_KEY` などのプレースホルダーを、コピーした実際の値に書き換えて保存します。

   ```js
   window.FIREBASE_CONFIG = {
     apiKey: "実際の値",
     authDomain: "実際の値",
     projectId: "実際の値",
     storageBucket: "実際の値",
     messagingSenderId: "実際の値",
     appId: "実際の値"
   };
   ```

   ※ これらは公開情報です（アプリの画面からも見える値なので、GitHubに公開しても問題ありません）。実際のアクセス制限は次の手順のFirestoreルールで行います。

## 3. Firestoreのアクセスルールを設定する

1. Firebaseコンソール →「Firestore Database」→「ルール」タブを開きます。
2. このフォルダの `firestore.rules` の中身を全部コピーし、ルールの入力欄に貼り付けて「公開」をクリックします。

   これにより、「名鑑」と「チームボード」だけ誰でも読み書きできる状態になります。ログイン機能はないため、**URLを知っている人は誰でもデータを編集できます**。身内利用が前提の設定です。より厳しく制限したい場合（例：オーナーだけ編集できるようにする等）は、Firebase Authenticationの導入が必要になります。

## 4. GitHubにアップロードする

1. GitHubで新しいリポジトリを作成します（Public / Privateどちらでも可。Privateの場合はGitHub Pagesの利用にProプラン等が必要な場合があります）。
2. リポジトリのページで「Add file」→「Upload files」を選び、このフォルダの3つのファイル（`index.html`, `firebase-config.js`, `firestore.rules`）をドラッグ＆ドロップしてアップロードし、コミットします。
   - コマンド操作は不要です。ブラウザだけで完結します。

## 5. GitHub Pagesを有効にする

1. リポジトリの「Settings」タブ →左メニューの「Pages」を開きます。
2. 「Build and deployment」の「Source」で `Deploy from a branch` を選択します。
3. 「Branch」で `main`（または `master`）と `/ (root)` を選んで「Save」します。
4. 数十秒〜数分待つと、ページ上部に公開URL（`https://ユーザー名.github.io/リポジトリ名/`）が表示されます。そのURLをみんなに共有してください。

## 6. 動作確認

1. 公開されたURLを開きます。
2. 右上のあたりに「自動保存中」という表示（緑色の丸）が出ていれば、Firebaseに正常に接続できています。
3. 選手を1人追加してみて、別のブラウザ（またはスマホ）で同じURLを開いたときに同じ選手が表示されれば成功です。

もし「Firebase未設定のため保存されません」という表示が出る場合は、`firebase-config.js` の値がまだプレースホルダーのままか、値の入力を間違えている可能性があります。もし「接続エラー」と表示される場合は、3.のFirestoreルールがまだ「公開」されていない可能性があります。

## 補足・制限事項

- **アクセス制限なし**：ログイン機能がないため、URLを知っていれば誰でも名鑑・ボードを編集できます。特定の人だけ全グループを見られるようにする、といった権限管理を追加したい場合はお知らせください。
- **無料枠について**：Firebaseの無料プラン（Sparkプラン）は、1日あたり読み取り5万回・書き込み2万回、保存容量1GiBまで無料です。8〜10グループ程度の利用であれば、通常は無料枠の範囲で十分収まります。
- **写真について**：アップロードした写真は自動的に縮小・圧縮されてからデータベースに保存されるため、大きな画像でも問題なく扱えます。
- 元々のClaude上でのバージョン（`db`機能を使った共有保存）も、そのまま別のツールとして引き続き利用できます。今回のGitHub Pages版はそれとは別の、独立したコピーです。
