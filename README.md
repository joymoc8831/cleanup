# スカッドボード（GitHub Pages版）

サッカーチームのフォーメーションボードアプリです。名鑑（選手一覧）とチームボード（グループごとのタブ）を、**外部サービスを一切使わず、GitHubリポジトリ自体をデータ保存先にして**全員で共有・自動保存します。

## できること

- 名鑑（FW・MF・DF／GK）を全員が同じ内容で閲覧・編集できます（写真・名前・一言）
- チームボードはグループごとにタブで切り替えられます。全グループの配置を誰でも見られます
- スマホ・PCどちらのブラウザからでも使えます
- **Firebaseなどの外部アカウント登録は不要**です。必要なのはGitHubアカウントだけです

## 仕組み（重要・簡単に）

このアプリは、名鑑やボードのデータを `data/roster.json` ・ `data/boards.json` という2つのファイルとして、あなたのGitHubリポジトリに保存します。誰かが選手を追加したり配置を変えたりすると、アプリがGitHubの「ファイルを更新するAPI」を呼び出して、そのファイルを**自動的にコミット**します。つまり「保存＝GitHubへのコミット」です。

- 他の人の変更は、数秒〜十数秒おきに自動で読み直して画面に反映します（リアルタイムのプッシュ通知ではなく、定期チェック方式です）
- 誰がいつ何を変更したかは、リポジトリの `data/` フォルダのコミット履歴としてそのまま残ります（変更履歴・巻き戻しの手段にもなります）
- ログイン機能はないため、**リンクを知っている人は誰でも編集できます**（身内利用が前提の設定です）

## 事前準備：ファイルの中身

このフォルダには次のファイルが入っています。

- `index.html` … アプリ本体（このまま使います。編集不要）
- `github-config.js` … GitHubリポジトリへの接続設定を書き込むファイル（**要編集**）
- `data/roster.json` … 名鑑の初期データ（54名分、写真・役職・一言入り。すでに用意済みです）
- `data/boards.json` … チームボードの初期データ（グループ×10、空の状態）
- `README.md` … この説明書

## 1. GitHubリポジトリを作る

1. [https://github.com/new](https://github.com/new) を開き、リポジトリ名を入力して作成します（Public / Privateどちらでも構いません。Privateの場合、GitHub Pagesの利用にProプラン等が必要な場合があります）。
2. 「Add file」→「Upload files」で、このフォルダの中身をすべて（`index.html`・`github-config.js`・`data/roster.json`・`data/boards.json`、`README.md`も含めて）そのままドラッグ＆ドロップしてアップロードし、コミットします。
   - フォルダごとドラッグすれば `data/` フォルダの構造ごとアップロードされます。
   - コマンド操作は不要です。ブラウザだけで完結します。

## 2. アクセストークンを発行する

このアプリがあなたの代わりにファイルを更新（コミット）できるように、GitHubのアクセストークンを1つ発行します。

1. GitHubの右上のアイコン →「Settings」→ 左メニュー下の方の「Developer settings」を開きます。
2. 「Personal access tokens」→「Fine-grained tokens」→「Generate new token」を選びます。
3. 以下のように設定します。
   - **Token name**: 好きな名前（例：`squad-board`）
   - **Expiration**: お好みで（期限が切れると自動保存できなくなるので、長め、または「No expiration」を推奨）
   - **Repository access**: 「Only select repositories」を選び、手順1で作ったリポジトリだけを選択します（**他のリポジトリは絶対に選ばないでください**）
   - **Permissions** → 「Repository permissions」の中の **Contents** を `Read and write` に設定します（他の権限はすべて `No access` のままで構いません）
4. 「Generate token」をクリックし、表示されたトークン（`github_pat_...` のような文字列）をコピーします。**この画面を閉じると二度と表示されないので、必ずこの時点でコピーしてください。**

⚠️ **重要**：このトークンは、次の手順で `github-config.js` というファイルにそのまま書き込みます。これは**アプリの画面ソースを見れば誰でも読み取れる状態**になるということです。ですので、

- 必ず「そのリポジトリ1つだけ」に絞ったFine-grainedトークンにしてください（手順3で解説した通りです）
- 必要な権限は **Contents: Read and write** だけにしてください
- こうしておけば、万が一トークンが見られても、影響範囲はこのリポジトリのファイル更新だけに限定されます

## 3. `github-config.js` を編集する

1. アップロードした `github-config.js` を、GitHub上で直接編集するか（ファイルを開いて鉛筆アイコンをクリック）、手元でこのフォルダの `github-config.js` を編集してから再アップロードします。
2. 次の値を書き換えます。

   ```js
   window.GITHUB_CONFIG = {
     owner: "あなたのGitHubユーザー名",
     repo: "作成したリポジトリ名",
     branch: "main",
     token: "手順2でコピーしたトークン",
     dataDir: "data",
     pollIntervalMs: 12000
   };
   ```

   - `owner` / `repo` は、リポジトリのURL（`https://github.com/ユーザー名/リポジトリ名`）から分かります。
   - `pollIntervalMs` は、他の人の変更をどのくらいの間隔で確認しにいくかです。同時に見る人数がかなり多くなりそうな場合は `20000`〜`30000`（20〜30秒）程度に伸ばしてください（下記「補足」参照）。

## 4. GitHub Pagesを有効にする

1. リポジトリの「Settings」タブ →左メニューの「Pages」を開きます。
2. 「Build and deployment」の「Source」で `Deploy from a branch` を選択します。
3. 「Branch」で `main`（または `master`）と `/ (root)` を選んで「Save」します。
4. 数十秒〜数分待つと、ページ上部に公開URL（`https://ユーザー名.github.io/リポジトリ名/`）が表示されます。そのURLをみんなに共有してください。

## 5. 動作確認

1. 公開されたURLを開きます。
2. 右上のあたりに「自動保存中」という表示（緑色の丸）が出ていれば、GitHubに正常に接続できています。
3. 選手を1人追加してみて、別のブラウザ（またはスマホ）で同じURLを開いたときに（`pollIntervalMs`で設定した間隔ほど待ってから）同じ選手が表示されれば成功です。
4. リポジトリの `data/roster.json` を開くと、追加した選手がコミットとして反映されているのが確認できます。

もし「GitHub未設定のため保存されません」という表示が出る場合は、`github-config.js` の値がまだプレースホルダーのままの可能性があります。もし「接続エラー」と表示される場合は、トークンの入力間違い・期限切れ、またはトークンの権限（Contents: Read and write）とリポジトリ選択を確認してください。

## 補足・制限事項

- **アクセス制限なし**：ログイン機能がないため、URL（正確にはトークン入りの `github-config.js` の中身）を知っていれば誰でも名鑑・ボードを編集できます。
- **リアルタイムではなく定期更新**：他の人の変更は `pollIntervalMs` の間隔（初期設定12秒）で反映されます。全員が同時に見ている状況が多い場合は、GitHub APIのアクセス回数（トークンごとに1時間5,000回まで無料）を消費しすぎないよう、間隔を長めに調整してください。目安として、同時に開いている人数×(3600÷間隔秒)×2回程度がおおよその消費量です。
- **同時編集について**：ほぼ同時に別々の人が保存しようとした場合は、アプリが自動的に最新版を取得し直してから再保存する仕組みになっています（通常は数百ミリ秒程度の遅れで自動的に解決されます）。
- **写真について**：アップロードした写真は自動的に縮小・圧縮されてからデータに保存されるため、大きな画像でも問題なく扱えます。ただし写真つきの名鑑データは容量が大きくなりやすく、`data/roster.json` へのコミットが積み重なるとリポジトリのサイズもゆるやかに増えていきます（数十〜百名規模の利用であれば通常問題になりません）。
- **変更履歴**：`data/roster.json`・`data/boards.json` の変更はすべてGitHubのコミット履歴として残るため、「いつ・どう変わったか」を後から確認したり、必要であれば古い版に戻すこともできます。
- 元々のClaude上でのバージョン（`db`機能を使った共有保存）も、そのまま別のツールとして引き続き利用できます。今回のGitHub Pages版はそれとは別の、独立したコピーです。
